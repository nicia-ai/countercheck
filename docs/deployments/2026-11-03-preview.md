## Ingress investigation and evidence limits

The first bounded burst used 140 random invalid keys and received 140 unauthorized responses, without observing rejection. That unsuccessful verification is retained. Native rate limits are approximate, location-specific and asynchronously synchronized; a short burst is not a strict-ceiling test. Deployed settings independently confirmed the intended 120/minute ingress and 60/minute per-key bindings.

A separate paced probe, at concurrency one with at least 120 ms between requests, used private readiness without credentials. In one observed edge location it received **121 × 401, then 1 × 429**, stopping on rejection. Readiness cannot dispatch inference; this probe made zero provider calls. The observation verifies ingress rejection, not an exact global or per-location ceiling. No confirmed implementation defect or code fix resulted from the investigation. [Cloudflare documents the synchronization and overshoot](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/#accuracy).

The named OAuth profile can provision Workers/D1 but returned 403 for zone ruleset reads. WAF configuration/coverage therefore remains unverified. Native ingress control permits controlled internal preview testing; it does not waive the production WAF gate, shared-NAT validation, human-adjudicated/locked-test model gates, provider privacy review or multi-location capacity testing.

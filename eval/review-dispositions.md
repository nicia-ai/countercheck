# Evaluation review dispositions

Fresh triage of the evaluation findings in the external structured review completed during this implementation. Runtime/deployment findings are owned separately. Historical result artifacts are immutable.

1. **Whole-batch envelope exclusions — intentional protocol; disclosure strengthened.** The approved design requires every per-text and compiled limit to pass (design § HTTP API, line 105), atomic completion and exactly one call without hidden smaller-group fallbacks (§ Kernel, lines 177–179), and separate isolated/bundled and operational views (§ Comparison systems / Protocol and scores, lines 283 and 295–296). A fixed two-pair request containing an invalid pair must fail atomically; an individually valid pair is not guaranteed to fit with 19 other comparisons. Greedy repacking would change the stress-test workload and call budget, so it was not introduced. New report protocol and Markdown explicitly identify fixed same-claim packing, isolated versus atomic-batch-envelope stress, whole-batch exclusion and disabled repacking. Documentation prohibits comparing that coverage as an isolated-pair quality score. A regression verifies that a fitting pair is excluded alongside an oversized member without dispatch, while the fitting pair succeeds in isolation.

2. **Entrypoint path guard — fixed.** `validateReplay` now lives in importable `eval/replay.ts`. `scripts/eval.ts` is an unconditional CLI entrypoint; tests no longer import a command with side effects. A real subprocess regression executes the CLI through a symlink whose name contains `#`, `?` and `%`, then requires the expected report to exist. It cannot pass through a silent exit-zero skip.

3. **Development “public performance claim” flag — renamed and clarified.** Public development measurements are valid development measurements; they do not establish held-out performance or production qualification. New report schema version 2 removes `public_performance_claim`, records `public_dataset` and an explicit `measurement_stage`, and always states `production_qualification: "not_assessed"`. CLI/subprocess tests check both synthetic and development classifications. Schema-version-1 saved results retain their original bytes and accompanying caveats; they were not rewritten retrospectively.

4. **Service client deadline versus server budgets — fixed.** Kernel/direct-provider evaluation retains its 3,000 ms default. The real-service route defaults to 6,000 ms total client transport time: 2,000 ms server body-read budget + 3,000 ms application budget + 1,000 ms transport margin. The provider's 2,500 ms budget is nested within the application budget. Explicit `--timeout-ms` overrides remain supported and are labeled as operator overrides. Reports expose the route scope and component budgets; replay identifies its deadline as not applied. Fake-clock service transport regressions show a valid 4.5-second response completes under the service default and remains a timeout under an explicitly selected 3-second stress budget. No live calls were made for verification.

## Independent adversarial review follow-up

- **M7, group-composition sampling bias — confirmed, quantified and disclosed; selection preserved.** The existing greedy development sampler is label-proportion matching, not uniform group sampling. New preparation metadata reports population and selected group-size histograms/means/maxima and mixed-label fractions. The new `eval/results/sampling-diagnostics-2026-11-03.json` reprocesses the cached native files and verifies the selected pair objects are exactly unchanged. VitaminC's 200 pairs come from 25 groups averaging 8 pairs, compared with a native mean of 3.82; SciFact's 199 pairs come from 151 groups averaging 1.32, compared with 1.80 natively. The evaluation guide limits interpretation accordingly. No historical manifest/result or selection algorithm was rewritten.
- **M8, paid results lost after dispatch — fixed with incremental checkpoints.** Before dispatch the CLI creates its output directory and exclusive prediction JSONL plus manifest-bound provenance. It syncs each completed batch before proceeding and closes the file in `finally`, retaining data on later errors. Unit tests verify append preservation and zero callback calls when checkpoint setup fails; an actual local HTTP subprocess test intentionally triggers summary failure after two completed fixture responses and verifies both predictions/metadata remain while no final report exists. There were no hosted calls. Partial checkpoints remain explicit partial observations and cannot silently bypass exact replay coverage or trigger automatic resume/retry.
- **L1, kernel versus production provider deadlines — intentional comparator difference, now explicit.** Kernel calls have an operation deadline; they do not reproduce authentication or the server's nested provider limit. New protocol metadata says kernel timing is not production-equivalent, and documentation directs operational measurements to the real service route. The service transport deadline fix above remains authoritative.
- **L2, replay invented dispatch metadata/provenance — fixed.** Replay now emits null route, presentation, batch size, concurrency and timeout rather than applying CLI defaults to imported inference. Original runtime details remain in source metadata. Reports pin the exact predictions bytes and available metadata SHA-256, while retaining manifest-hash validation. Subprocess tests verify the null fields and file hash.
- **L3, collapsed internal provider errors — fixed.** Evaluation preserves safe internal `ServiceError.code` values for outages, malformed output and provider timeouts. Unit tests verify distinct outcomes and ensure provider message text is not published. Ordinary unexpected exceptions still map to a generic safe error.
- **L4, bundled contrast context — intentional stress-test limitation, disclosed.** Same-claim revision snippets can share a model context in bundled runs. The guide and report protocol identify atomic batch/distractor stress and prohibit presenting those scores as directly comparable isolated-pair quality. The default remains isolation; there is no silent repacking or inference fallback.
- **L5, development claim flag — fixed above.** Public measurement stage is separate from unassessed production qualification in report schema 2; historical artifacts remain immutable.
- **L9, service client redirects — fixed.** The client uses `redirect: "manual"`, cancels 3xx response bodies and reports `service_redirect_rejected`; it never sends a follow-up request. A regression checks manual fetch policy, one call, body cancellation and a safe failure without the redirect URL or any semantic verdict.

Other independent adversarial findings concern runtime/deployment/operator behavior and are handled outside this evaluation assignment.
